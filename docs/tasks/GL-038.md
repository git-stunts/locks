## 1. Background Context

A remote Git transport adds partitions, retries, stale local state, and uncertain publication outcomes.

## 2. The Question

Can a remote Git authority provide the required admission and failure guarantees?

## 2b. What decision waits on it

Establish whether a supported remote authority protocol is feasible before an implementation proposal.

## 2c. What would settle it

- [ ] Define the authoritative publication point and admission receipt.
- [ ] Model partitions, uncertain push results, lease clocks, and retry identity.
- [ ] Require resource-side fencing where stale writers must be stopped.
- [ ] Record an explicit reject or proceed decision and new tasks if needed.

Golden: Model one successful remote admission.
Edges: Include disconnected and delayed clients.
Known failure modes: Never start protected work after an ambiguous admission.
Fuzz and stress: Use bounded simulation first; no live shared remote experiments.

## 2d. Aperture

A successful network demonstration cannot establish partition safety.

## 2e. Possible answers and what each implies

Keep local-only scope; use a supported coordination service; or specify a remote protocol with proven boundaries.
