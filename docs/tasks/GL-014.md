## 2. Problem Description

Claim planning directly replaces a planned deletion in T_AFTER. That transition bypasses the normal plan interface.

## 2b. Proposed Solution

Introduce one checked redirect operation for the intended delete-to-replacement transition.

## 2c. Alternatives considered and rejected

Do not weaken plan_set to accept arbitrary replacement.

## 2d. Acceptance Criteria

- [ ] Require the expected snapshot value and prior planned deletion.
- [ ] Reject unrelated contradictory transitions.
- [ ] Preserve expired-owner eviction, descendants, and atomic replacement.
