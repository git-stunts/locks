## 1. Background Context

The root is a tree, not a commit journal. The GC experiment shows that an empty common parent does not retain old sibling state or unpublished candidates.

## 2. The choice

Record a finite retention and crash-durability contract that is compatible with the single-root authority.

## 2b. Options and consequences

- Offline destructive maintenance with finite retained evidence.
- A separately designed bounded online snapshot retention protocol.
- Reject unbounded successful-history retention as the default maintenance policy.

## 2c. Rests on

Use the pinned baseline and source paths below. Review exact candidate evidence before acceptance.

- [ ] State what active snapshots, candidate objects, successful history, and evidence must survive and for how long.
- [ ] Start destructive reclamation with explicit quiescence unless an online pin/admission protocol closes every selection-to-pin race.
- [ ] Define object/ref/directory hardening and supported crash model; distinguish atomic publication from power-loss durability.
- [ ] Define store format identification, unsupported-client refusal, offline migration, and rollback compatibility.
- [ ] Set measurable growth bounds; do not use JSON OID strings or an empty parent as reachability protection.
