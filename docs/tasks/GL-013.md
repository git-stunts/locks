## 1. Background Context

Record validation writes normalized numbers into R_FIELD. The same array also represents stored field text.

## 2. Problem Description

Record validation writes normalized numbers into R_FIELD. The same array also represents stored field text.

## 2b. Proposed Solution

Keep raw record fields immutable and expose validated numeric values through a separate interface.

## 2c. Alternatives considered and rejected

Do not change record bytes merely to simplify decoding.

## 2d. Acceptance Criteria

- [ ] Preserve exact stored values and record object identity.
- [ ] Use normalized values for all arithmetic and numeric JSON.
- [ ] Keep default handling for supported legacy fields explicit.

## 2e. Test Plan

Golden: Round-trip canonical numeric fields.
Edges: Cover leading zeros, absent family values, overflow, and malformed numbers.
Known failure modes: Reject bad records before liveness or output.
Fuzz and stress: Use finite numeric boundary fixtures.
