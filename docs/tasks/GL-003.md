## 1. Background Context

Cached test execution is bounded; scripts/docker-run.py still invokes an unguarded build on a missing or changed image. Rust adds toolchain and dependency preparation that must share the same budgets.

## 2. Problem Description

Cached test execution is bounded; scripts/docker-run.py still invokes an unguarded build on a missing or changed image. Rust adds toolchain and dependency preparation that must share the same budgets.

## 2b. Proposed Solution

Provide one reusable, fail-closed preparation and execution boundary for Bash, Git, Python, and the selected Rust toolchain.

## 2c. Alternatives considered and rejected

A partial result that depends on a later repair is not independently mergeable. Retaining the working reference remains the fallback until the scoped candidate passes.

## 2d. Acceptance Criteria

- [ ] Reuse the owned image/worker and inspect fix/guard-bootstrap before changing its provider.
- [ ] Account for acquisition, build, export/load, writable layers, dependency caches, Cargo targets, temporary data, and host/container logs.
- [ ] Enforce aggregate 20 GiB build, 4 GiB data, and 128 MiB log limits; monitor host and Docker backing free space with a 50 GiB floor.
- [ ] Make timeout, cancellation, monitor failure, and quota breaches terminate all owned descendants.
- [ ] Pass cached and fresh setup paths in a supported real environment, or refuse unsupported setup before it writes unaccounted output.
- [ ] Keep source and generated build outputs out of toolchain image layers; use one compatible Cargo target with CARGO_INCREMENTAL=0 for review campaigns.

## 2e. Test Plan

- Golden: matching cached image runs without a build.
- Edges: absent/mismatched image and compiler/dependency cache at budget.
- Failures: disk/memory/process/log exhaustion, timeout, interrupted export, and failed monitoring stop the workload.
