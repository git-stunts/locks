## 1. Background Context

The current wrapper verifies before launch and after completion but does not renew or stop work at expiry. Wait deadlines do not flow through each inner publication attempt. These are core lifecycle concerns for the staged port.

## 2. The choice

Record compatible default and opt-in lifecycle rules for paths, semaphore slots, waiting, supervision, and failed renewal.

## 2b. Options and consequences

- Preserve manual renewal as the default and add an explicit supervised mode.
- Use declared finite operation deadlines, with zero-wait semantics stated separately.
- Require a resource adapter for actual stale-write enforcement.

## 2c. Rests on

Use the pinned baseline and source paths below. Review exact candidate evidence before acceptance.

- [ ] Preserve the existing advisory default unless a deliberate versioned change is selected; define an opt-in guarded renewal mode.
- [ ] Define atomic renewal of every requested acquisition, expiry margins, ownership supersession, operational failure, and renewal that would shorten an existing lease.
- [ ] Define stop-and-report behavior for failed renewal/lost ownership, plus grace, forced group termination, cleanup, and detached-child exclusions.
- [ ] Separate wall-clock lease interoperability from monotonic elapsed deadlines in Rust; explicitly state the Bash waiting clock boundary.
- [ ] Define a complete admission deadline, finite plumbing I/O budget, zero-wait one-attempt semantics, uncertain publication, cancellation, and cleanup deadlines.
- [ ] State that process stopping and heartbeat renewal cannot fence a paused writer or retract remote effects.
