## 1. Background Context

Normal commands correctly fail closed on inconsistent authority. Recovery must not silently discard reservations still in use or treat an old root as safe solely because it decodes.

## 2. The choice

Record supported recovery classes, quiescence requirements, authority selection, and rollback guarantees.

## 2b. Options and consequences

- Explicit offline recovery for named damage classes.
- Backup restore with an explicit authority-loss assessment.
- Refuse ambiguous cases and require operator reconciliation.

## 2c. Rests on

Use the pinned baseline and source paths below. Review exact candidate evidence before acceptance.

- [ ] Separate malformed records, missing objects, index inconsistency, incomplete legacy migration, and native lock residue.
- [ ] Require stopped clients and a byte-preserving backup before destructive repair.
- [ ] Define refusal for ambiguous ownership and unsupported damage rather than inferring a winner.
- [ ] Specify version-compatible restore, post-recovery verification, and what rollback cannot promise.
