## 1. Background Context

The source audit found a strict-create mismatch in gix and experimental SHA-256 gates in libgit2. No native library has passed the complete operation matrix.

## 2. The Question

Which native Git operations can replace CLI plumbing with demonstrated semantic parity and measured benefit?

## 2b. What decision waits on it

The scoped implementation, support claim, or delivery outcome named in this card waits on the result.

## 2c. What would settle it

- [ ] Pin the actual library, bindings, feature flags, build recipe, and supported object/ref formats in the existing bounded toolchain.
- [ ] Build and execute the full current operation matrix, including raw symbolic lookup, strict same-target creation refusal, expected-old-root CAS, packed refs, migration, and environment isolation.
- [ ] Test operational errors, busy locks, corrupt/missing objects, exact raw bytes, and stated durability behavior; API names and source review do not satisfy runtime parity.
- [ ] Measure the supported native subset against the stable Git CLI backend with identical complete workloads and durability.
- [ ] Record fully-native, hybrid, or no-adoption decision; keep CLI publication/fallback for unsupported or unresolved semantics.
- [ ] No shipping native backend is implied by the decision; add an implementation card only for a selected verified scope.
