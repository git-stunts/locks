## 1. Background Context

The state protocol is sound enough to preserve. Bash global arrays, mutable decoder fields, planner exits, and implicit transitions make further lifecycle work hard to review.

## 2. Problem Description

The state protocol is sound enough to preserve. Bash global arrays, mutable decoder fields, planner exits, and implicit transitions make further lifecycle work hard to review.

## 2b. Proposed Solution

Add a non-default Rust core that reads, validates, plans, and conditionally publishes through Git CLI plumbing.

## 2c. Alternatives considered and rejected

A partial result that depends on a later repair is not independently mergeable. Retaining the working reference remains the fallback until the scoped candidate passes.

## 2d. Acceptance Criteria

- [ ] Pin a compatible Rust toolchain and dependencies in the reusable guarded environment; Cargo output stays in one capped target.
- [ ] Keep raw record text/bytes separate from checked numeric/domain values and preserve stored object/acquisition identity.
- [ ] Model immutable snapshots, validated records, expected-old-root transitions, explicit redirects, decisions, and typed errors.
- [ ] Make liveness and relationship rules shared while keeping diagnostic and mutation decisions distinct.
- [ ] Expose pure planner tests with independent fixtures; planners return results instead of printing or terminating the process.
- [ ] Use a backend boundary for object/tree/ref operations, but implement it with supported Git CLI semantics including strict create and no-deref.
- [ ] Keep bin/git-locks and the default installation unchanged; this preparatory crate must build and test independently.

## 2e. Test Plan

- Golden: coherent snapshot and candidate round-trip in both hashes.
- Edges: stale/absent/symbolic/packed roots, preserved raw fields, and conflicting plan edits.
- Failures: corrupt authority, contradictory redirects, unavailable objects, and operational errors fail closed without success receipts.
