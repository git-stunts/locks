## 1. Background Context

Single-file consumers need a way to verify the executable and schema they download.

## 2. Problem Description

Single-file consumers need a way to verify the executable and schema they download.

## 2b. Proposed Solution

Add checksums, signed provenance, and a documented independent verification procedure to the release pipeline.

## 2c. Alternatives considered and rejected

Checksums alone detect corruption but do not establish publisher identity.

## 2d. Acceptance Criteria

- [ ] Bind executable, schema, source revision, and build recipe.
- [ ] Verify signatures and checksums from a clean consumer fixture.
- [ ] Demonstrate failure after artifact or identity substitution.
- [ ] Use a draft or test release until publication receives explicit approval.

## 2e. Test Plan

Golden: Verify authentic draft artifacts.
Edges: Cover missing signatures, wrong identities, and altered bytes.
Known failure modes: Failed verification must not install an artifact.
Fuzz and stress: Keep release logs and artifacts within declared budgets.
