## 1. Background Context

## 2. Problem Description

Bash, Python, graph validation, and later Rust checks need explicit tiers. A fast tier cannot replace required correctness and integration coverage.

## 2b. Proposed Solution

Define reproducible fast and full validation tiers for the reference and Rust migration.

## 2c. Alternatives considered and rejected

A partial result that depends on a later repair is not independently mergeable. Retaining the working reference remains the fallback until the scoped candidate passes.

## 2d. Acceptance Criteria

- [ ] Choose pinned Python lint/format checks with generated/vendored exclusions; reconcile contributor docs and entry points.
- [ ] Measure the local fast tier against the existing 120-second target under recorded conditions, listing every omission.
- [ ] Keep full state, family, semaphore, root-ref, lifecycle, Unicode, and observation-calibration suites required for applicable merge candidates.
- [ ] Define how Cargo format/lint/tests and cross-implementation parity join the full gate as Rust stages land.
- [ ] Run all execution through guarded workers; do not silently fall back to host tools or a new cache.

## 2e. Test Plan

- Golden: documented tier runs reproducibly.
- Edges: missing tool, changed image, newly added suite, and generated-file exclusions.
- Failures: a fast-only result cannot satisfy the full merge gate.
