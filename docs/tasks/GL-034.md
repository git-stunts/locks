## 1. Background Context

Reflogs and an append-only history chain have different identity, retention, and publication properties.

## 2. The choice

Should the tool retain queryable history, and which publication model preserves its guarantees?

## 2b. Options and consequences

No durable history; bounded retained snapshots; or a specified event chain with a coherent read basis.

## 2c. Rests on

Use the baseline sources and prerequisite evidence listed in this card. Recheck their current state.

- [ ] Define event identity, ordering, retention, and query guarantees.
- [ ] Do not claim that an extra ref remains coherent merely because writers update it together.
- [ ] Measure growth requirements and preserve the retention policy.
- [ ] Create an implementation card only for an accepted contract.

## 2d. Who decides, and by when

The assigned task owner decides within the active authorization before dependent implementation starts. James decides changes to product scope, access, and publication. No calendar deadline is assigned.

## 2e. What is blocked until then

Dependent implementation and any new guarantee remain blocked until the decision is recorded.
