## 1. Background Context

Operators need a safe reclamation workflow. Detached GC on release and immediate pruning of an active store are not accepted defaults.

## 2. Problem Description

Operators need a safe reclamation workflow. Detached GC on release and immediate pruning of an active store are not accepted defaults.

## 2b. Proposed Solution

Provide bounded store measurement and maintenance that preserves all required authority and retained objects.

## 2c. Alternatives considered and rejected

A partial result that depends on a later repair is not independently mergeable. Retaining the working reference remains the fallback until the scoped candidate passes.

## 2d. Acceptance Criteria

- [ ] Implement GL-011 quiescence, retention, format, and durability policy.
- [ ] Account for loose/packed objects, live authority, retained snapshots, and generated logs with a clear measurement basis.
- [ ] Prove repeated acquire/release and maintenance cycles stay within the declared growth bound.
- [ ] Refuse unsafe online pruning and unsupported versions; never touch unrelated refs or unknown files in self mode.
- [ ] Define cancelled maintenance, full storage, failed GC, and backup retention behavior.

## 2e. Test Plan

- Golden: reclaim disposable historical objects while preserving current authority.
- Edges: required retained snapshots, both hashes, packed refs, and self mode.
- Failures: active clients, disk threshold, cancellation, and pruning errors fail closed with bounded evidence.
