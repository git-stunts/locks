## 1. Background Context

The public Bash 4 claim includes interpreters that fail on empty arrays. Local Bash 4.4 validation exists on an unpublished branch.

## 2. Problem Description

The public Bash 4 claim includes interpreters that fail on empty arrays. Local Bash 4.4 validation exists on an unpublished branch.

## 2b. Proposed Solution

Integrate the tested Bash 4.4 floor and a real minimum-interpreter CI job. Reconcile current main before publication.

## 2c. Alternatives considered and rejected

Preserve Bash 4.0 support only if actual interpreter tests establish it; current evidence does not.

## 2d. Acceptance Criteria

- [ ] Reject unsupported Bash with the documented exit and diagnostic before store access.
- [ ] Run the full production CLI suite with the actual minimum interpreter.
- [ ] Align startup checks, install guidance, and CI with the same supported floor.

## 2e. Test Plan

Golden: Supported interpreter runs all commands.
Edges: Unsupported interpreters refuse before writes.
Known failure modes: Invalid stdin descriptors preserve the intended refusal.
Fuzz and stress: Reuse bounded compilation output; do not start a second build cache.
